# 蜡笔猫导航：资源采集与推荐 Agent 方案

> 状态（2026-10-26）：一、后台采集 Agent 已实现，在 `collector-agent` 分支，等待验收后合入 main；实现细节见《蜡笔猫导航-v1-架构》§9。二、前台推荐 Agent 尚未开工。
> 范围：本方案超出原 MVP（MVP 不做自动爬取海量资源、AI 意图搜索），2026-10-25 用户决定新增，MVP 文档 §2.4 已注明。

## 一、后台采集 Agent（先做）

**配置**
- 后台新增「Agent 设置」：模型服务商（OpenAI 兼容格式：Base URL + API Key + 模型名）、每次采集上限、每月花费上限
- API Key 加密后存库（密钥放环境变量），后台只显示末四位

**采集来源（白名单，不爬任意网站）**
- MCP 官方 Registry、GitHub 搜索与主题（mcp-server、ai-agent 等）、awesome 类清单
- Hugging Face、Product Hunt 等有公开 API 的站点
- 管理员也可以直接贴一个链接让它整理

**流程**
1. 拉取候选 → 按网址/GitHub 地址与现有资源去重
2. 模型按我们的数据结构输出：名称、原创简介与介绍、分类（只能选现有 6 类）、标签（优先复用现有标签）、官网/GitHub、定价类型、关联工具
3. 服务端用 zod 校验，再检查链接是否可访问
4. 进入「候选箱」：附来源链接、Star 数、最近更新时间、模型给出的理由和置信度
5. 管理员逐条「上架 / 改后上架 / 存草稿 / 拒绝」，拒绝过的不再重复推送

**触发**：后台手动「开始采集」，可选每天定时一次；永不自动上架

## 二、前台推荐 Agent（资源过百后做）

- 只从本站已上架资源里推荐，每条结果必须对应真实详情页，服务端校验返回的资源，杀掉编造
- 先用关键词/分类粗筛，再让模型排序并写推荐理由；资源多了再上向量检索（Neon 支持 pgvector）
- 匿名可用，按 IP 限流 + 每日花费上限；不记录用户输入内容
- 前提：登录限流从内存换成数据库或 Upstash

## 三、已定事项（2026-10-25）

- 模型服务商：采用 OpenAI 兼容格式，管理员在后台自行填写 Base URL、API Key、模型名，可随时更换（DeepSeek、通义、OpenAI 等）。
- 首批采集来源：按上文执行。
- 先做后台采集 Agent；前台推荐 Agent 等资源过百、限流换成数据库后再做。

## 四、实现与草案的差异

- 「每月花费上限」未实现：目前只记录每次运行的 token 用量，靠单次条数上限（默认 8、最多 20）控制成本。
- 加密密钥 `AGENT_ENCRYPTION_KEY` 未设置时由 `AUTH_SECRET` 派生；模型 API Key 只在后台填写，加密存库，不进环境变量。
- 定时采集：Vercel Cron 每天 UTC 01:00（北京时间 09:00），需配置 `CRON_SECRET`。
- Product Hunt 必须有 Token，没有就自动跳过。
