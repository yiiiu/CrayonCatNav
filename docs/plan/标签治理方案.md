# 标签治理方案（2026-10-26）

> 状态：第一阶段已实现（collector-agent 分支，待提交与预览验收）；第二、三阶段待排期。
> 背景：采集 Agent 上线后，模型会持续产出新标签。原实现有两个问题，且随资源增长标签维护会越来越重。

## 0. 现状问题

1. **新中文标签上架即报错**：`tagSlugFor` 只认 `prisma/tag-slugs.ts` 的映射，模型新建的中文标签（如「视频剪辑」）在「直接上架」时报错，审核频繁卡住。
2. **中英混合标签静默并入**：`tagSlugFor` 兜底时删掉非 `[a-z0-9]` 字符，「AI绘画」变成 `ai`，`planTags` 发现 slug 已存在就**悄悄挂到现有的 AI 标签**上，不报错。
3. **标签无限膨胀**：模型可自由新建，近义词（视频剪辑 / 视频编辑）会各建一个，前台筛选越来越碎，后台只能手工合并。

原则：标签是**受控词表**。模型只能用已启用的标签；新词先进待定池，由管理员决定启用、归并或忽略。slug 统一用英文（与现有 70 余个标签一致），不用拼音。

## 第一阶段：止住膨胀 + 修复 slug（本次实施）

### 1.1 数据模型
- `Tag.aliases String[]`：别名。模型或审核员写别名时直接映射到该标签。
- 新表 `TagSuggestion`（待定池，独立于 `Tag`，不会出现在前台）：
  - `name`、`slug`（唯一）、`status`：`open` 待定 / `accepted` 已启用 / `merged` 已归并 / `ignored` 已忽略
  - `hits`：被提了几次；`candidateIds`：来自哪些候选；`tagId`：启用或归并后对应的标签
- 迁移：`20261026020000_tag_governance`

### 1.2 采集时
- 提示词：`tags` **只能**从「现有标签」里选；确实没有合适的，可在 `suggestedTags` 里提最多 2 个 `{name, slug}`（slug 为小写英文连字符）。
- `cleanModelOutput` 清洗：
  - `tags`：按名称或别名（忽略大小写）映射到现有标签的规范写法；不认识的丢弃。
  - `suggestedTags`：名称/别名命中现有标签 → 并入 `tags`；命中已忽略的待定词 → 丢弃；slug 不合法或与现有标签 slug 撞名（名字不同）→ 丢弃，**不合并**。
- 候选入库后，`suggestedTags` 写入待定池（按 slug upsert，`hits + 1`、记录候选 id）。
- 候选 payload 新增 `suggestedTags`（旧数据默认为空，向后兼容）。

### 1.3 审核时
- 候选卡片的标签输入：现有标签写名字；新标签写成 `名字:slug`（如 `视频剪辑:video-editing`），模型建议的新标签会预填成这种格式，可直接改。
- `planTags` 查找顺序：现有标签同名 → 别名 → 输入里带的 slug → `tag-slugs.ts` 映射 → 纯英文名按规则转换 → 报错。
- **slug 撞名报错**：slug 已被另一名称的标签使用 → 上架时报错并指到标签字段；存草稿时丢弃并提示。不再静默并入。
- 审核员在上架时写了新标签 = 直接启用：建标签，同 slug 的待定词标为 `accepted`。

### 1.4 `tagSlugFor` 不再退化
- 名称含非 ASCII 字符且不在映射表 → 直接抛错，不再删掉中文拼剩下的部分。
- 纯英文名继续按规则转换。
- `tag-slugs.ts` 冻结，只给种子和历史标签用；以后新标签不需要补映射。

### 1.5 待定池后台（`/admin/tag-suggestions`）
- 列出待定词：名称、slug、被提次数、来自几条候选；按次数倒序，被提 ≥3 次的高亮。
- 操作：
  - **启用**：建成正式标签（校验名称、slug 不冲突）。
  - **归到…**：选一个现有标签，把这个词记成它的别名；以后模型再写这个词就直接映射。
  - **忽略**：以后模型再提这个词直接丢弃。
- 导航显示待定数量徽标。
- 分类标签页的标签行可编辑别名（逗号分隔），别名不能与其他标签的名称/别名重复。

### 1.6 测试
- 「AI绘画」不再变成 `ai`；非 ASCII 无映射抛错。
- 别名映射、建议词清洗（并入 / 忽略 / 撞名丢弃 / 非法 slug 丢弃）。
- 审核输入 `名字:slug` 解析；slug 撞名上架报错、草稿丢弃。

## 第二阶段：清理存量（资源过百后）

- **合并工具**：标签 A 合并到 B，迁移资源关联、A 变成 B 的别名、旧 slug 301 到新 slug（保 SEO）。
- **相似标签提示**：用已有的 `pg_trgm` 计算名称相似度，列出「可能重复」的标签对，一键合并或忽略。
- **低频标签**：只挂 0–1 条已上架资源且建了超过 30 天的，标黄建议合并或停用。
- **停用状态**：`Tag.status`（active / disabled），停用后前台不展示、模型不可选，历史关联保留。

## 第三阶段：结构化（资源过千再考虑）

- **标签分组**：能力（图像生成、代码审查…）/ 形态（开源、自托管、桌面客户端…）/ 场景。每组限制数量，前台筛选按组展示。
- 「定价」这类已有字段的维度不再做成标签。

## 日常维护成本
- 每周扫一眼待定池（第二阶段起加上相似提示），几分钟。
