# 资源详情页优化方案

> 2026-10-26 提出并确认，第一期已在 collector-agent 分支实现（见文末「实现状态」）。

## 背景与目标

现状：详情页只有标题卡（名称、一句话简介、标签、官网 / GitHub 按钮）和一段介绍。用户想知道一个网站是干嘛的，必须跳到官网，多了一次二次触达成本。

目标：用户不跳转也能在 10 秒内判断「是什么、能干嘛、适不适合我、怎么开始」。

## 第一期：补内容（收益最大）

### 1. 官网预览图
- 优先取官网的 og:image（多数产品都有设计好的封面图），没有再用 GitHub 仓库的社交卡片。
- 采集 Agent 入候选箱前自动抓取；后台资源编辑页可手动修改。
- 只接受 https；详情页用原生 `<img>` 懒加载，`referrerPolicy="no-referrer"`。
- 后续可选：转存到自己的存储（如 Vercel Blob），避免外站图片失效或防盗链。
- 不做 iframe 嵌入官网：多数网站禁止嵌入（X-Frame-Options / CSP），而且慢、有安全风险。

### 2. 结构化介绍
| 字段 | 说明 | 上限 |
| --- | --- | --- |
| highlights 核心功能 | 每条一句话 | 6 条 |
| useCases 适合谁 / 典型场景 | 每条一句话 | 4 条 |
| quickstart 快速上手 | 安装命令或配置片段，前台代码块 + 一键复制 | 2000 字 |
| platforms 支持平台 | Web / macOS / Windows / Linux / iOS / Android / 命令行 / API / VS Code / 浏览器插件 | — |
| pricingNote 定价说明 | 如「免费 50 次/月，Pro $20/月」 | 200 字 |

字段全部可空，为空时前台不展示对应区块，老数据不受影响。

### 3. 页面布局
- 标题卡：左侧名称、简介、标签、按钮；右侧官网预览图（点击访问官网）。
- 主栏：它能做什么 → 适合谁 → 快速上手 → 详细介绍。
- 右侧信息栏（移动端移到主栏上方）：官网域名、GitHub 仓库、定价（类型 + 说明）、平台、分类、更新时间。
- 没有任何结构化字段的资源保持原单栏布局。

### 4. 内容来源
- 采集 Agent 提示词要求产出以上字段：只根据来源数据写，quickstart / 定价没有明确来源就留空，不编造；人工审核后上架。
- 后台资源编辑页可直接编辑全部字段（多行文本一行一条）。
- 待做：后台「AI 补全」按钮——对已有资源抓取官网 / README 生成草稿，人工确认后保存，不自动覆盖。

## 第二期：活数据
- GitHub 仓库按天刷新 Star、License、主要语言、最近提交时间。
- 展示 README 摘要。
- 巡检失效链接，官网挂了在后台提示。

## 第三期：帮用户做选择
- 「同类替代」对比：与 2–3 个同类资源在定价、开源、平台上并排对比。
- 优缺点 / 编辑点评。

## 不做
- iframe 嵌入官网、实时抓取官网全文展示：加载慢、易被拦截，还有版权风险。

## SEO 收益
- 详情页从「薄页面」变成有实质内容的页面。
- 后续可输出 SoftwareApplication 结构化数据，预览图也可作为分享封面（openGraph.images）。
