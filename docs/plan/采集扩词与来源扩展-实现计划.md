# 采集关键词 AI 扩词与来源扩展：实现计划

> 规格：`docs/spec/采集关键词AI扩词与来源扩展方案.md`。状态：阶段一已实现（2026-10-26，待预览验收）；阶段二未开始。分类说明改为弹层预览后点「替换」，未另弹 ConfirmDialog。
> 分支：`collector-agent`。与「自托管部署」互不依赖，可先做。

## 0. 已定决策

| 决策 | 结论 |
|---|---|
| AI 输出是否直接保存 | 否，只填输入框，人工保存 |
| 规则在哪执行 | 服务端纯函数 `lib/agent/term-rules.ts`，提示词只做引导 |
| 命中校验 | GitHub / HF 真实接口计数；无 Token 时最多校验 8 个，缓存 24 小时 |
| 新来源选择 | 只用公开免费接口：HN Show、HF 模型、OpenRouter、可配 awesome |
| 配置存储 | 继续用 `CategoryCollectConfig.config`（Json），扩展 zod schema，旧数据按默认值补齐，无需迁移表结构 |

## 1. 待验证（实施前）

1. 各新来源接口的参数、返回字段、速率限制与使用条款（HN Algolia、HF models、OpenRouter models）。
2. GitHub 搜索 `total_count` 在无 Token 时的速率与准确性。
3. 通用 awesome 解析器对 3–5 个主流清单（含 Agent Skills、AI 编程类清单）的解析质量，fixture 入库。

## 2. 任务拆分

### 阶段一：AI 扩词（约 2 天）

**T1 规则与提示词（0.5 天）**
- `lib/agent/term-rules.ts`：`normalizeTerm`、`FIELD_RULES`（格式复用 `collect-config.ts` 的 zod、上限、黑名单）、`classifyTerms(candidates, { existing, otherCategories, field, hits })` → `{ term, status: "ok" | "broad" | "blocked", reason }[]`。
- `lib/agent/term-prompt.ts`：`buildTermPrompt(context, field)`，输出 JSON 约定、规则版本号。
- 测试：归一化、跨分类重复、黑名单、过泛 / 无结果判定、上限截断。

**T2 命中校验（0.5 天）**
- `lib/agent/term-hits.ts`：`githubTopicHits`、`githubKeywordHits`、`hfSpaceHits`；复用 `sources/http.ts`，带 GitHub Token（若有）；内存缓存 24 小时（`Map` + 过期时间，单实例足够）。
- 测试：fixture 模拟接口返回与限流。

**T3 领域服务与 Action（0.5 天）**
- `lib/domain/term-suggest.service.ts`：`suggestTerms(categoryId, field, draft)`：取分类说明、15 条已上架资源样例（`resource.repo`）、各分类已配置词（`category-collect.service`）→ 调模型（45 秒超时）→ 规则过滤 → 命中校验 → 返回；10 分钟结果缓存。
- `suggestDescription(categoryId)`：生成分类说明草稿。
- `app/admin/(protected)/actions.ts`：`suggestTermsAction`、`suggestDescriptionAction`（`requireAdmin`，不 refresh、不写库）。

**T4 界面（0.5 天）**
- `components/admin/TermWand.tsx`（客户端）：魔法棒按钮 + 弹层（复用 Select 的 popover 定位与无闪烁处理）+ 词签 + tooltip（语义 / 理由 / 命中）+「全部加入推荐」。通过 ref 操作对应 input 的值，派发 input 事件。
- `CategoryCollectConfigs.tsx`：在 GitHub 主题、GitHub 关键词、HF 搜索词、分类说明标签旁接入；分类说明替换前用 ConfirmDialog。
- 样式进 `agent.module.css`：三种状态色、满额提示。

### 阶段二：来源扩展（约 3 天）

**T5 来源框架（0.5 天）**
- `lib/agent/sources/registry.ts`：`SourceDef { key, label, hint, needsToken, configSchema, defaults, fetch }`；现有 5 个来源改为注册形式（行为不变）。
- `collect-config.ts`：`sources` 与各来源参数改为由注册表生成；旧配置经 schema 默认值补齐。
- `AgentSetting` 全局开关：新增布尔列（hn、hfModels、openrouter）——需要一个迁移；或改为 `enabledSources String[]`（推荐，后续加来源不再加列），旧列保留兼容一版后删除。

**T6 新来源（1.5 天）**
- `sources/hn.ts`：Show HN，搜索词 + 最低分数 + 近 30 天，取帖子外链，过滤 github.com 以外的产品官网也收。
- `sources/hf-models.ts`：按搜索词 / pipeline 标签，trending 或 likes 排序。
- `sources/openrouter.ts`：只取近 30 天新增模型（按 `created`），映射到模型/API 分类。
- 每个来源 fixture + 测试；失败只记该来源错误。

**T7 可配 awesome 清单（0.5 天）**
- `collect-config.ts`：`awesomeRepos: string[]`（`owner/repo`，≤3）。
- `sources/awesome.ts`：通用解析（去掉 MCP 专属章节判断，保留官方标注识别），README 地址由仓库名拼 raw 地址，默认分支先查 GitHub API。
- 数据迁移：seed / 读取时 MCP 分类若无配置，默认 `["punkpeye/awesome-mcp-servers"]`。
- 魔法棒「推荐 awesome 清单」：AI 给候选 → GitHub API 校验存在、star ≥ 500、近 6 个月有更新。

**T8 界面与文档（0.5 天）**
- 分类采集配置表单按注册表渲染新来源的开关与参数；新字段接入魔法棒。
- 采集 Agent 设置的全局来源开关增加新来源。
- 架构文档 §9、README、项目简报更新。

## 6. 风险

| 风险 | 应对 |
|---|---|
| GitHub 搜索限流导致命中校验慢/失败 | 限制校验个数、缓存、失败标「未校验」不阻断 |
| 模型生成的词看似合理但语义偏 | 命中数 + 跨分类去重 + 人工点选三重把关 |
| HN 外链多为非 AI 产品 | 搜索词限定 + 分数门槛 + 模型整理阶段按分类说明判定归属，不符合直接丢弃 |
| awesome 清单格式各异 | 通用解析 + fixture；解析为 0 条时在运行详情提示 |
| 新来源增多导致单次运行超时 | 每来源条数上限 + 总条数仍受 `maxPerRun` 约束 |

## 7. 工作量

约 5 人天：阶段一 2 天，阶段二 3 天。
