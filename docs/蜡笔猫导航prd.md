# 蜡笔猫导航｜产品需求文档（PRD）

> 版本：v1.0（产品规划）  
> 日期：2026-10-08  
> 定位：AI 资源导航 + 在线效率工具平台  
> 阶段：产品定义；本文件描述中长期方向，不代表首版全部上线。

## 1. 产品概述

### 1.1 产品愿景

**蜡笔猫导航**是面向 AI 开发者、AI 爱好者及独立创作者的资源发现与在线工具平台，让用户从“找到工具”进一步完成“了解、配置和使用”。

核心链路：**发现资源 → 了解与比较 → 使用站内工具 → 前往目标产品 / 完成操作 → 收藏复访**。

### 1.2 目标用户

| 人群 | 核心问题 | 主要诉求 |
|---|---|---|
| AI 开发者 / Vibe Coding 用户 | MCP、Skills、模型服务分散且配置繁琐 | 快速找到适用资源并生成可用配置 |
| AI 爱好者 | 工具很多，不清楚差异 | 可信的介绍、筛选与入门教程 |
| 独立创作者 | AI 创作链路需要组合多种工具 | 按任务寻找工具和工作流 |
| 技术内容创作者 | 分享的工具和教程缺少统一沉淀 | 可传播的资源详情和工具入口 |

### 1.3 产品差异化

1. **导航与工具双核心**：不止外链收录，优先把资源连接到可直接使用的在线工具。
2. **可操作的资源详情**：提供用途、兼容客户端、配置说明、注意事项和关联工具，而非仅有简介。
3. **AI 垂直起步**：优先覆盖 AI 编程、MCP、Agent Skills、模型 API，再逐步延展至综合工具。
4. **低门槛使用**：基础搜索和多数工具无需登录；敏感内容尽量在浏览器本地处理。

### 1.4 非目标

- 不做无差别“收录越多越好”的网址大全。
- 初期不做 API 中转站、云端运行第三方代码或托管密钥。
- 不以 AI 聊天功能替代每个工具的专业操作界面。
- 不承诺第三方工具价格、兼容性永远实时准确。

## 2. 产品结构与模块

一级导航建议：**发现 / 工具箱 / 工作流（后续） / 收藏（后续）**；首页提供统一搜索入口，首版可先分别检索资源和工具。

| 模块 | 核心能力 | 规划阶段 |
|---|---|---|
| 首页与搜索 | 分类入口、精选资源、热门工具、搜索 | MVP |
| 资源导航 | 分类、标签、关键词搜索、资源详情、外链 | MVP |
| 在线工具箱 | MCP 配置生成器、格式转换、模型成本估算 | MVP |
| 内容管理后台 | 资源与工具管理、发布上下线、基础统计 | MVP |
| 用户收藏 | 登录、收藏夹、最近使用、跨设备同步 | V1.1 |
| 工作流中心 | 按目标串联多个资源和工具 | V1.2 |
| AI 意图推荐 | 自然语言需求 → 资源与工具推荐 | V1.2+ |
| 商业化 | 合作推广、联盟链接、高级增值工具 | 验证流量和需求后 |

## 4. 功能需求

### 4.1 资源导航

**资源分类（初始建议）**：AI 编程、MCP 服务、Agent Skills、AI 模型/API、GitHub 开源项目、AI 创作。

资源条目包含：名称、唯一 slug、简介、分类、标签、官网链接、GitHub 链接（可选）、图标（可选）、兼容平台（可选）、价格模式（未知/免费/免费增值/付费）、开源属性（可选）、更新时间、发布状态。

详情页包括：适用场景、核心能力、使用方式或教程、相关资源、关联站内工具、外链跳转；信息不完整时不虚构字段。

**交互规则**：支持关键词、分类、标签筛选；无结果时提供清空条件；外部链接清晰标识并安全新开标签；错误或失效链接可通过后台下架或更正。

### 4.2 在线工具箱

#### 工具 A：MCP 配置生成器

输入：客户端类型（首版 Cursor / Claude Desktop；其他客户端后续验证）、服务名、启动方式（首版 stdio）、command、args、env 键值对。输出：对应客户端配置 JSON、复制、下载、语法校验与必填项提示。

重要约束：仅在已验证的配置模式下生成文件；每个客户端采用独立适配器，防止误以为不同客户端字段完全相同；不上传或保存用户输入的密钥；展示“请勿将真实密钥分享给他人”的提醒。

#### 工具 B：JSON / YAML / TOML 转换器

支持粘贴或输入文本、选择源格式与目标格式、语法校验、转换、复制、下载、清空。对各格式不能无损对应的值明确告知（如日期/特殊数值/注释），避免声称完全无损。

尽可能在浏览器本地转换，不记录用户输入内容。

#### 工具 C：模型 Token 成本估算器

用户手动输入输入 Token、输出 Token、对应的每百万 Token 单价、请求次数；输出单次与合计预估成本，注明币种和计算公式：

`成本 = (输入Token / 1,000,000 × 输入单价 + 输出Token / 1,000,000 × 输出单价) × 请求次数`

首版允许手动填写价格，后续才考虑有来源与更新时间的模型价格表；不将“估算”表述为真实账单。

### 4.3 管理后台

- 管理员登录及访问控制；无需公开注册。
- 分类、标签与资源的新增、编辑、删除、草稿/发布状态。
- 资源 slug 唯一性校验、必填字段校验、外链格式校验。
- 首页精选配置与工具入口状态管理。
- 基础数据：站内资源详情访问、站内工具打开和工具执行次数（匿名聚合；不记录用户输入内容）。

### 4.4 搜索与 SEO

- 资源、分类、工具页面具备独立标题、描述和可分享 URL。
- 可索引页面采用服务端渲染或静态生成；提供 sitemap.xml、robots.txt、canonical。
- 搜索支持名称、简介和标签；初期采用数据库搜索或轻量全文检索，不引入复杂向量数据库。
- 明确区分编辑推荐、自然排序与付费推荐，付费内容必须显著标注。

## 5. 典型用户旅程

### 场景一：发现 MCP 并完成配置

1. 用户搜索“文件系统 MCP”。
2. 进入资源详情，确认功能与兼容客户端。
3. 点击“使用 MCP 配置生成器”。
4. 表单根据已验证的参数预填公开字段；密钥始终由用户本地输入。
5. 用户生成并复制配置，在目标客户端自行配置。

### 场景二：估算模型调用费用

1. 用户从模型相关资源页面进入成本估算器。
2. 输入 Token 和单价。
3. 查看公式与估算结果；复制结果。

### 场景三：从内容平台进入

1. 用户看到社交平台上的 AI 工具教程。
2. 打开蜡笔猫导航的具体资源详情页。
3. 阅读介绍，并直接使用关联站内工具。
4. 需要时返回工具箱使用其他工具。

## 6. 设计体验原则

- 品牌风格：友好、轻松、清晰可信，以“蜡笔猫”作为记忆点；避免过度幼稚化导致开发者工具缺乏专业感。
- 统一卡片样式与搜索体验；工具页面优先保证输入、输出和操作反馈清晰。
- 响应式布局，兼容桌面与移动端；键盘可操作、表单有标签、对比度可读。
- 图标/插画可独立设计，**不应妨碍加载速度与核心操作**。
- UI 设计与技术实现前，先确认视觉方案并复用统一主题 token / 组件。

## 7. 技术与数据原则

**技术栈建议（可按既有项目调整）**：Next.js + TypeScript + PostgreSQL + Prisma 或同等成熟方案；使用模块化工具注册表维护工具定义与路由，不必第一版就做插件运行沙箱。

主要实体：

| 实体 | 关键字段 |
|---|---|
| Resource | id, slug, name, summary, description, categoryId, websiteUrl, githubUrl, pricingType, status, updatedAt |
| Category | id, slug, name, sortOrder |
| Tag | id, slug, name |
| ResourceTag | resourceId, tagId |
| Tool | id, slug, name, description, category, status, sortOrder |
| ResourceTool | resourceId, toolId, relationType |
| Admin | id, authId, role |
| AnalyticsEvent | type, resourceId/toolId, date, count（聚合） |

安全要求：管理员端服务端权限校验；输入严格校验；外链协议白名单；敏感字段不进入日志；前端工具尽量本地运算；依赖库及第三方数据源需审查许可和维护情况。工具涉及外部网络访问的能力单独做安全设计，不能无约束代理任意用户 URL。

## 8. 增长与商业化设想

- **内容获客**：搜索友好的资源详情、教程、配置指南，与小红书/短视频内容联动。
- **站内留存**：详情页直达实用工具、工具之间关联推荐。
- **后续商业模式**：联盟推广、明确标识的付费推荐位、付费高级工具、团队功能。先通过实际流量和需求验证，不在 MVP 内实现支付。

## 9. 衡量指标

首版先建立数据口径，目标值上线后根据真实基线迭代：

- **发现价值**：资源详情访问量、站内搜索次数、搜索无结果率。
- **工具价值**：工具页访问量、实际执行次数、工具使用完成率。
- **关联价值**：资源详情 → 关联工具的点击率。
- **留存线索**：7 天回访用户占比（仅在隐私许可和技术条件允许时统计）。
- **质量指标**：资源失效链接率、配置生成错误反馈、页面加载与错误率。

不以“总收录数量”作为唯一成功标准。

## 10. 版本路线图

| 版本 | 目标 | 核心交付 |
|---|---|---|
| MVP v0.1 | 验证“导航 + 工具”是否有真实需求 | 资源搜索详情、3 个工具、后台、基础 SEO/统计 |
| v0.2 | 提升内容覆盖与用户反馈 | 资源修订流程、关联推荐优化、体验改进 |
| v1.0 | 增加复访能力 | 用户收藏、最近使用、可选账号体系 |
| v1.1+ | 从工具平台扩展到任务平台 | 工作流模板、AI 意图推荐、按需付费服务 |

## 11. 主要风险与对策

| 风险 | 对策 |
|---|---|
| SEO 流量不稳定 | 多渠道内容获客，提供可直接使用的工具价值 |
| 信息失效或价格变化 | 标注更新时间、定期人工复核，不编造实时数据 |
| 工具功能过多导致维护成本上升 | MVP 控制数量、统一注册接口、按使用数据扩展 |
| 凭据泄漏 | 本地执行、避免存储输入、配置页面显著安全提示 |
| 收录或内容版权争议 | 原创介绍，遵守第三方版权、商标、API 和抓取规则 |
| 变现影响公信力 | 编辑推荐与商业推广明显区分 |

## 12. 决策原则

本 PRD 是产品方向基线。**实际第一版开发范围以《蜡笔猫导航-第一版MVP.md》为准**，未列入 MVP 的能力默认不实现；任何新增需求先评估用户价值、复杂度和对首版上线的影响。
