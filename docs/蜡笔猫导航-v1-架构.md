# 蜡笔猫导航 v1 架构方案（MVP P0）

## 1. 技术选型
| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | Next.js 16（App Router，开启 Cache Components）+ TypeScript | 路由与 MVP 页面清单一一对应；SSR/SSG 满足 SEO；同仓库写后台与 API |
| 样式 | CSS Modules + 设计 token（CSS 变量，沿用蜡笔风） | 无 CDN、组件复用、主题集中 |
| 数据库 | PostgreSQL 15+ + Prisma 7（adapter-pg） | 关系模型清晰；pg_trgm 支持中文模糊搜索 |
| 认证 | Auth.js v5 凭据登录（JWT 会话），仅管理员；proxy.ts 拦截 + requireAdmin 查 Admin 表二次校验 | 不做普通用户账号 |
| 工具库 | yaml、smol-toml、原生 JSON（打包进 bundle） | 纯前端本地处理，不上传 |
| 缓存 | `"use cache"` + cacheLife/cacheTag；后台写入后 server action 内 updateTag | 后台改内容无需重新部署 |
| 埋点 | /api/track → DailyMetric 按日聚合计数 | 不记录原始输入与密钥 |
| 部署 | 海外：Vercel + 托管 Postgres（如 Neon / Supabase），备选 Docker 自托管 | 已定海外部署，无需备案（2026-10-09） |

## 3. 数据模型（在 PRD 第 7 节 / MVP 第 6 节基础上补约束与索引）
- Category(id, name, slug UNIQUE, sortOrder)
- Tag(id, name, slug UNIQUE)
- Resource(id, slug UNIQUE, name, summary, description, categoryId FK, websiteUrl?, githubUrl?, iconUrl?, pricingType?, status ENUM(draft|published|archived), featuredOrder? , updatedAt)
  - 索引：(status, categoryId)、featuredOrder、pg_trgm GIN(name, summary)
- ResourceTag(resourceId, tagId) PK 复合；索引 tagId
- Tool(id, slug UNIQUE, name, description, status, sortOrder)
- ResourceTool(resourceId, toolId, relationType)
- Admin(id, email UNIQUE, passwordHash(bcrypt), role ENUM(owner|editor), createdAt)
- DailyMetric(date, eventType, resourceId?, toolId?, count) UNIQUE(date, eventType, resourceId, toolId) NULLS NOT DISTINCT（PG15+）
- 公共查询统一走 publishedOnly()，从仓储层杜绝草稿泄漏。

## 4. 关键流程
1. 搜索：首页提交 → /resources?q= ；服务端按 name/summary 三元组 + 标签名匹配，cat/tag 联合筛选，分页 20 条，URL 即状态可分享。
2. 详情 → 工具：ResourceTool 存在时显示 RelatedToolCTA，链接带非敏感预填参数（如 /tools/mcp-config?server=github&cmd=npx），点击埋点 resource_to_tool_click。
3. 后台发布：server action → requireAdmin → zod 校验 → 写库 → updateTag('resources') / updateTag('home') → 读回返回。
4. 工具执行：全部浏览器内计算；tool_execute 仅上报工具 id 与成功/失败。

### 4.5 模块化工具注册表（PRD 第 7 节）
目标：新增一个工具只需「加一个目录 + 在注册表登记一行」，工具中心、路由元数据、sitemap、埋点白名单、资源关联全部从注册表派生；首版不做插件沙箱。

```ts
// lib/tools/registry.ts
export type ToolDefinition = {
  slug: string;                 // 与 Tool 表 slug、路由 /tools/{slug} 一致
  name: string;                 // 中文名
  description: string;          // 卡片与 SEO 描述
  category: 'ai-config' | 'data' | 'cost';
  icon: string;                 // 蜡笔风图标 key
  privacy: 'local';             // 首版全部本地运算；未来出现 'network' 需单独安全评审
  status: 'enabled' | 'hidden' | 'beta';
  prefillParams?: readonly string[]; // 允许从资源详情预填的非敏感查询参数白名单
  load: () => Promise<{ default: React.ComponentType }>; // 懒加载工具 UI
};
export const toolRegistry = [mcpConfig, dataConverter, tokenCost] as const satisfies readonly ToolDefinition[];
export const getTool = (slug: string) => toolRegistry.find(t => t.slug === slug);
```

规则：
- 代码注册表是「工具能力」唯一来源；数据库 Tool 表只存运营状态（上下线、排序）与 ResourceTool 关联，启动/种子脚本按注册表 upsert，后台不可新增注册表外的 slug。
- /tools 中心 = 注册表 ∩ Tool.status=enabled，按 sortOrder 排序。
- /tools/[slug] 动态路由：getTool 不存在或停用 → notFound()；generateMetadata 读注册表；sitemap 遍历注册表。
- 预填：RelatedToolCTA 只拼接 prefillParams 白名单内的参数；env/密钥类字段永不预填。
- 埋点：tool_open / tool_execute 的 toolId 必须在注册表内，否则 /api/track 丢弃。
- 新增工具 checklist：lib/tools/{slug}/（logic.ts + logic.test.ts + meta.ts）→ components/tool/{slug}/ UI → 注册表一行 → 种子同步。

## 5. 安全
- 管理 API 服务端鉴权（proxy.ts + requireAdmin 双层；Next 16 中 middleware 已更名 proxy），不靠隐藏按钮。
- 外链仅允许 https，统一 rel="noopener noreferrer" target="_blank"。
- MCP 生成器：env 值默认掩码，不进 URL、不入埋点、不发请求；不提供远程执行。
- 输出转义，描述字段用受限 Markdown 渲染。
- 登录限流 + 安全 Cookie（HttpOnly、SameSite=Lax、Secure）。当前限流为内存实现，Vercel 多实例上线前需换成 Upstash 或数据库计数。

## 9. 工程实现记录
- 代码位于 web/（2026-10-09 搭建骨架）。
- 阶段 2 内容闭环（2026-10-09）：
  - 分层：`lib/validation`（zod，纯函数）→ `lib/domain/*.service.ts`（业务规则：slug 唯一、发布需至少一个链接和一个标签、有资源的分类不可删、精选最多 12 个且仅已发布）→ `lib/data/*.repo.ts`（Prisma；公共读取一律 `publishedOnly` + `"use cache"` + `cacheTag`）。
  - 后台写操作集中在 `app/admin/(protected)/actions.ts`：首行 `requireAdmin()`，写后 `updateTag(resources/home/taxonomy/resource:slug)`。后台布局在 Suspense 内 `await connection()` 后再校验身份，后台页面不参与预渲染。
  - 前台列表 URL 即状态（q/cat/tag/page，每页 20），搜索走 name/summary/标签名 ILIKE，pg_trgm GIN 索引已写进 schema（`@@index(..., type: Gin, ops: raw("gin_trgm_ops"))`），`migrate diff` 无漂移。
  - **详情页真实 404**：Cache Components 下首次访问未预渲染的 slug 会先流式输出外壳，页面内 `notFound()` 只能得到 200 + noindex。解决：`proxy.ts` 对 `/resources/:slug` 先做一次轻量存在性查询（`lib/data/resource-exists.ts`，pg 直连，仅查已发布），不存在/未发布则 `rewrite` 到构建期预渲染好的 `/resources/__none__`（status 404）。查询失败时放行，交给页面处理。
  - 构建期需要可连通的数据库（首页、详情预渲染会查库）；无库时 generateStaticParams 退化为只预渲染 404 占位。
  - 本地验证可用 embedded-postgres 的二进制（initdb + pg_ctl，端口 5433）；`prisma migrate diff` 生成迁移时只取 stdout，避免 CLI 提示混入 SQL。

### 9.x 阶段 3 工具闭环（2026-10-09）

  - Google Search Console：服务账号 JWT（RS256，`lib/analytics/google-auth.ts`）换 token，调 `POST https://www.googleapis.com/webmasters/v3/sites/{siteUrl}/searchAnalytics/query`（scope `webmasters.readonly`，type=web，dataState=all，PT 昨天往前 28 天），取总计 / Top 10 查询词 / Top 10 落地页。
  - Bing Webmaster：`https://ssl.bing.com/webmaster/api.svc/json/{GetRankAndTrafficStats|GetQueryStats|GetPageStats}?siteUrl=&apikey=`，总量取每日流量近 28 天，查询词 / 页面为周数据按曝光加权聚合。
  - 两者都在 `lib/data/search-console.ts`（server-only）里 `"use cache"` + `cacheLife({ stale: 1h, revalidate: 6h, expire: 24h })` + `cacheTag("search-console")`；未配置显示「未接入」，失败显示「暂时取不到」（错误不缓存、不含密钥），不影响页面其他部分。图表为服务端手绘风 SVG（`components/admin/overview`），无图表依赖。
  - 站点验证：根 layout `metadata.verification` 读取 `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION`（输出 `msvalidate.01`），未设置不输出。
- **Vercel 需新增的环境变量**（均为服务端变量，不要加 `NEXT_PUBLIC_` 前缀）：

  | 变量 | 用途 | 怎么获取 |
  | --- | --- | --- |
  | `GOOGLE_SITE_VERIFICATION` | GSC 站点验证 meta | GSC → 添加资源 → 选「网址前缀」填 `https://crayon-cat-nav.vercel.app/` → 验证方式选「HTML 标记」→ 复制 `content="…"` 里的值。配置后重新部署，再回 GSC 点「验证」。 |
  | `GSC_SITE_URL` | 要查询的 GSC 资源 | 与上一步资源完全一致，如 `https://crayon-cat-nav.vercel.app/`（网址前缀，带末尾 `/`）；若用网域资源则写 `sc-domain:example.com`。 |
  | `GSC_SERVICE_ACCOUNT_JSON` | 服务账号凭据（推荐） | Google Cloud 控制台新建/选择项目 → 「API 和服务」启用 **Google Search Console API** → 「IAM 和管理 → 服务账号」新建服务账号（无需授予项目角色）→ 「密钥 → 添加密钥 → JSON」下载 → 把整份 JSON 内容粘贴为变量值。 |
  | `GSC_CLIENT_EMAIL` + `GSC_PRIVATE_KEY` | 上一项的替代写法 | 分别取 JSON 里的 `client_email` 和 `private_key`（换行可保留为 `\n`）。两种写法二选一。 |
  | （GSC 授权） | 让服务账号能读数据 | GSC → 设置 → 用户和权限 → 添加用户 → 填服务账号邮箱（`…@….iam.gserviceaccount.com`）→ 权限选「受限」即可。 |
  | `BING_SITE_VERIFICATION` | Bing 站点验证 meta（可选） | 推荐直接在 Bing Webmaster Tools 首页选「从 Google Search Console 导入」，授权后站点自动验证，不需要此变量；如手动添加站点并选「HTML Meta 标记」，复制 `msvalidate.01` 的 content 值。 |
  | `BING_SITE_URL` | 要查询的 Bing 站点 | 与 Bing Webmaster 里的站点地址一致，如 `https://crayon-cat-nav.vercel.app/`。 |
  | `BING_WEBMASTER_API_KEY` | Bing Webmaster API 访问 | Bing Webmaster Tools → 右上角设置（齿轮）→ API 访问 → 「API 密钥」→ 生成并复制。 |

  不配置以上变量时，总览中对应卡片显示「未接入」，其余功能不受影响。密钥只在服务端读取，不进入客户端 bundle、日志或埋点（构建产物 `.next/static` 已检索确认）。
