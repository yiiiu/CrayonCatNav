# 蜡笔猫导航 v1 架构方案（MVP P0）

## 1. 技术选型
| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | Next.js（App Router）+ TypeScript | 路由与 MVP 页面清单一一对应；SSR/SSG 满足 SEO；同仓库写后台与 API |
| 样式 | CSS Modules + 设计 token（CSS 变量，沿用蜡笔风） | 无 CDN、组件复用、主题集中 |
| 数据库 | PostgreSQL + Prisma | 关系模型清晰；pg_trgm 支持中文模糊搜索 |
| 认证 | Auth.js 凭据登录，仅管理员；Admin 表二次校验 | 不做普通用户账号 |
| 工具库 | yaml、smol-toml、原生 JSON（打包进 bundle） | 纯前端本地处理，不上传 |
| 缓存 | ISR + 发布时 revalidateTag | 后台改内容无需重新部署 |
| 埋点 | /api/track → DailyMetric 按日聚合计数 | 不记录原始输入与密钥 |
| 部署 | 海外：Vercel + 托管 Postgres（如 Neon / Supabase），备选 Docker 自托管 | 已定海外部署，无需备案（2026-10-09） |

## 3. 数据模型（在 PRD 第 7 节 / MVP 第 6 节基础上补约束与索引）
- Category(id, name, slug UNIQUE, sortOrder)
- Tag(id, name, slug UNIQUE)
- Resource(id, slug UNIQUE, name, summary, description, categoryId FK, websiteUrl?, githubUrl?, iconUrl?, pricingType?, status ENUM(draft|published|archived), featuredOrder? , updatedAt)
  - 索引：(status, categoryId)、featuredOrder、pg_trgm GIN(name, summary)
- ResourceTag(resourceId, tagId) PK 复合；索引 tagId
- Tool(id, slug UNIQUE, name, description, status, sortOrder)
- ResourceTool(resourceId, toolId, relationType)
- Admin(id, authId UNIQUE, role)
- DailyMetric(date, eventType, resourceId?, toolId?, count) UNIQUE(date, eventType, resourceId, toolId)
- 公共查询统一走 publishedOnly()，从仓储层杜绝草稿泄漏。

## 4. 关键流程
1. 搜索：首页提交 → /resources?q= ；服务端按 name/summary 三元组 + 标签名匹配，cat/tag 联合筛选，分页 20 条，URL 即状态可分享。
2. 详情 → 工具：ResourceTool 存在时显示 RelatedToolCTA，链接带非敏感预填参数（如 /tools/mcp-config?server=github&cmd=npx），点击埋点 resource_to_tool_click。
3. 后台发布：server action → requireAdmin → zod 校验 → 写库 → revalidateTag('resources','home') → 读回返回。
4. 工具执行：全部浏览器内计算；tool_execute 仅上报工具 id 与成功/失败。

### 4.5 模块化工具注册表（PRD 第 7 节）
目标：新增一个工具只需「加一个目录 + 在注册表登记一行」，工具中心、路由元数据、sitemap、埋点白名单、资源关联全部从注册表派生；首版不做插件沙箱。

```ts
// lib/tools/registry.ts
export type ToolDefinition = {
  slug: string;                 // 与 Tool 表 slug、路由 /tools/{slug} 一致
  name: string;                 // 中文名
  description: string;          // 卡片与 SEO 描述
  category: 'ai-config' | 'data' | 'cost';
  icon: string;                 // 蜡笔风图标 key
  privacy: 'local';             // 首版全部本地运算；未来出现 'network' 需单独安全评审
  status: 'enabled' | 'hidden' | 'beta';
  prefillParams?: readonly string[]; // 允许从资源详情预填的非敏感查询参数白名单
  load: () => Promise<{ default: React.ComponentType }>; // 懒加载工具 UI
};
export const toolRegistry = [mcpConfig, dataConverter, tokenCost] as const satisfies readonly ToolDefinition[];
export const getTool = (slug: string) => toolRegistry.find(t => t.slug === slug);
```

规则：
- 代码注册表是「工具能力」唯一来源；数据库 Tool 表只存运营状态（上下线、排序）与 ResourceTool 关联，启动/种子脚本按注册表 upsert，后台不可新增注册表外的 slug。
- /tools 中心 = 注册表 ∩ Tool.status=enabled，按 sortOrder 排序。
- /tools/[slug] 动态路由：getTool 不存在或停用 → notFound()；generateMetadata 读注册表；sitemap 遍历注册表。
- 预填：RelatedToolCTA 只拼接 prefillParams 白名单内的参数；env/密钥类字段永不预填。
- 埋点：tool_open / tool_execute 的 toolId 必须在注册表内，否则 /api/track 丢弃。
- 新增工具 checklist：lib/tools/{slug}/（logic.ts + logic.test.ts + meta.ts）→ components/tool/{slug}/ UI → 注册表一行 → 种子同步。

## 5. 安全
- 管理 API 服务端鉴权（middleware + requireAdmin 双层），不靠隐藏按钮。
- 外链仅允许 https，统一 rel="noopener noreferrer" target="_blank"。
- MCP 生成器：env 值默认掩码，不进 URL、不入埋点、不发请求；不提供远程执行。
- 输出转义，描述字段用受限 Markdown 渲染。
- 登录限流 + 安全 Cookie（HttpOnly、SameSite=Lax、Secure）。

## 6. 开发步骤（与 MVP 文档第 7 节一致）
1. 工程骨架：Next.js、tokens、ui 组件、Prisma 迁移、管理员认证（约 1 周）
2. 内容闭环：分类标签 → 资源 CRUD → 列表/详情 → 首页精选（约 1.5 周）
3. 工具闭环：格式转换 → MCP 生成器 → Token 估算（约 1 周）
4. 资源与工具关联、预填参数（约 0.5 周）
5. 上线质量：SEO、响应式、埋点、错误态、安全复核、部署（约 1 周）
