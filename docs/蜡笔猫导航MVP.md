# 蜡笔猫导航｜第一版 MVP 需求与验收清单

> 版本：v0.1  
> 日期：2026-10-08  
> 目标：以最小可用版本验证“AI 资源导航 + 在线工具箱”的用户需求  
> 原则：**先上线可用闭环，不提前开发会员、支付、AI 聊天和复杂工作流。**

## 1. MVP 成功定义

用户能够在不登录的情况下：

1. 搜索或筛选 AI 资源。
2. 在详情页看到真实介绍、官网/GitHub、关联工具。
3. 打开工具箱并成功使用至少一项在线工具。
4. 通过清晰的复制或下载操作获取结果。

管理员能够独立维护资源、分类、标签与精选列表，无须每次修改都重新部署。

首版主要验证：**有没有用户进入工具页并实际执行操作，以及资源详情能否带来工具使用。**

## 2. 范围边界

### 2.1 必做 P0

| 编号 | 模块 | 需求 | 优先级 |
|---|---|---|---|
| M01 | 首页 | 品牌头部、搜索框、六大分类入口、精选资源、工具快捷入口 | P0 |
| M02 | 资源列表 | 按名称/简介/标签搜索；按分类和标签筛选；分页或加载更多 | P0 |
| M03 | 资源详情 | 名称、简介、描述、标签、官网/GitHub（存在时）、关联工具、更新时间 | P0 |
| M04 | 工具中心 | 工具卡片列表、工具介绍、进入工具、独立可分享 URL | P0 |
| M05 | MCP 配置生成器 | Cursor / Claude Desktop 的已验证 stdio 配置生成、校验、复制、下载 | P0 |
| M06 | 格式转换器 | JSON / YAML / TOML 格式解析与转换、报错、复制和下载 | P0 |
| M07 | Token 成本估算器 | 手动单价、Token 数、次数、结果与公式 | P0 |
| M08 | 管理后台 | 管理员登录；资源/分类/标签 CRUD；草稿与发布；精选配置 | P0 |
| M09 | SEO 基础 | 标题/描述、可读路径、sitemap、robots、canonical | P0 |
| M10 | 运行质量 | 响应式、空状态、错误状态、基础埋点、输入安全 | P0 |

### 2.2 可后置 P1

资源反馈入口、失效链接检查、更多 MCP 客户端适配、资源互相关联、基础教程内容模板、简单站内排序优化。

### 2.3 本次明确不做

普通用户账号、跨设备收藏、付费系统、AI 意图搜索、AI 工作流生成、自动爬取海量资源、自动更新第三方模型价格、远程执行 MCP 服务、云端存储用户 API Key、开放投稿社区。

### 2.4 MVP 之外的待办

- **后台采集 Agent + 人工审核**（2026-10-25 用户决定新增，**超出原 MVP 范围**）：管理员配置 OpenAI 兼容模型后，Agent 从白名单来源（MCP 官方 Registry、GitHub、awesome 清单、Hugging Face、Product Hunt、管理员贴的链接）整理候选资源进「候选箱」，每条都需人工审核才上架，永不自动上架。§2.3 的「自动爬取海量资源」仍然不做——本功能只读白名单来源、每次限量，并由人工把关。实现见架构文档 §9「后台采集 Agent」。
- **前台自然语言推荐 Agent**：推迟到资源过百、登录限流换成数据库计数之后再评估（2026-10-25）。
- **GEO 待定**（生成式引擎优化：让 ChatGPT / Perplexity / Copilot 等 AI 搜索更好地引用本站）：方向、指标与做法均未确定，2026-10-25 记录，暂不实施。

## 4. 详细验收标准

### M01 首页

- [ ] 顶部有清晰品牌名“蜡笔猫导航”和主要导航“发现 / 工具箱”。
- [ ] 搜索框输入关键词后跳转到资源结果页，并保留关键词。
- [ ] 六个分类可进入对应筛选结果：AI 编程、MCP、Agent Skills、AI 模型/API、开源项目、AI 创作。
- [ ] 首页精选由后台配置，空列表时不显示空白卡片区域。
- [ ] 热门工具区固定至少展示首版 3 个工具。

### M02 资源搜索/列表

- [ ] 已发布资源可被搜索；草稿/下架资源不会对公众展示。
- [ ] 支持关键词（名称、简介、标签）和分类/标签联合筛选。
- [ ] 支持清空筛选；无结果时显示明确提示。
- [ ] 列表显示名称、简介、分类、标签与必要外链提示。
- [ ] 支持分页或“加载更多”，URL 可分享并保留筛选条件。

### M03 资源详情

- [ ] 资源 slug 唯一，访问不存在或下架的 slug 返回 404。
- [ ] 介绍、官网/GitHub、标签与更新时间按真实数据渲染。
- [ ] 没有 GitHub 地址时隐藏入口，不展示空链接。
- [ ] 有关联工具时显示显著入口（例如“生成 MCP 配置”）；无关联时不强行推荐。
- [ ] 外链只允许安全协议（例如 HTTPS），外开标签添加安全属性。

### M04 工具中心

- [ ] 3 个工具都存在独立路由与页面介绍。
- [ ] 工具卡片标题、用途、入口可用。
- [ ] 输入错误、操作成功、复制失败时都有对应反馈。

### M05 MCP 配置生成器

- [ ] 仅支持已验证的 Cursor 与 Claude Desktop **stdio** 配置模式；按客户端生成对应结构。
- [ ] 支持服务名称、command、args、env 增删改，并校验必填项。
- [ ] 生成结果为可解析 JSON，复制与下载正常。
- [ ] 针对不同操作系统/客户端的配置文件位置显示经核实说明；未知时不推测。
- [ ] 明确提醒 API Key 属于敏感数据；不向服务器传输、持久化或埋点记录输入内容。
- [ ] 不提供远程命令执行功能。

### M06 JSON/YAML/TOML 转换器

- [ ] 输入合法的源格式文本后，可选择目标格式并得到可解析结果。
- [ ] 非法格式时展示可定位的错误信息（若解析器支持行列号）。
- [ ] 支持复制、下载、清空；没有输入时禁用或提示转换。
- [ ] 对注释、类型差异等无法保证无损的情况给出提示。
- [ ] 输入内容本地处理，不上传服务器。

### M07 Token 成本估算器

- [ ] 输入 Token 数、输出 Token 数、输入单价、输出单价、请求次数均有非负/合理范围校验。
- [ ] 使用每百万 Token 的单价口径，准确计算单次和总估算成本。
- [ ] 显示币种和公式；价格由用户输入，不伪称实时官方价。
- [ ] 小数精度和四舍五入规则清晰；结果可复制。

### M08 管理后台

- [ ] 未登录访问 `/admin` 被拒绝或重定向登录。
- [ ] 管理 API 在服务端实施身份与权限校验，而非只隐藏按钮。
- [ ] 可以创建、修改、发布和下架资源；slug 与必填项校验有效。
- [ ] 可以维护分类和标签并配置首页精选顺序。
- [ ] 公共页面不会显示草稿内容。
- [ ] 编辑页面错误有反馈，保存成功后实际数据可读回。

### M09 / M10 基础质量

- [ ] 首页、分类列表、资源详情及工具页可被直接访问和分享。
- [ ] 页面拥有合适的 title、description、canonical，站点提供 sitemap/robots。
- [ ] 桌面、平板、手机上页面无严重溢出，核心操作可点击。
- [ ] 统计事件至少覆盖 `resource_view`、`tool_open`、`tool_execute`、`resource_to_tool_click`；不记录原始输入与密钥。
- [ ] 404、无数据、加载失败、转换失败均有处理。
- [ ] 无外部 CDN 运行时依赖；公共资源和组件尽量复用统一设计 token。

## 5. 初始内容与测试样本

建议首批人工审核收录 **30～50 条真实资源**，分布于六个分类；先验证质量与内容结构，再扩充至 100～200 条。每条至少有：名称、简介、分类、合法链接、标签、状态。尽量为 MCP 类资源录入与配置生成器的关联信息。

工具测试样本至少包括：

- MCP：无参数命令、带 args、带 env、空命令、含引号/反斜杠、切换客户端、复制/下载。
- 转换：普通对象/数组、嵌套结构、布尔/null/数字、特殊字符串、非法格式、注释或类型差异。
- 成本：全零、常见输入、非常小的单价、大 Token 量、多次请求、非法负数。

**注意**：资源库初始条目与客户端格式不能靠模型臆造，必须核对原始官网或仓库资料。

## 6. 数据最小模型

```text
Category(id, name, slug, sortOrder)
Tag(id, name, slug)
Resource(id, slug, name, summary, description, categoryId,
         websiteUrl?, githubUrl?, iconUrl?, pricingType?,
         status, featuredOrder?, updatedAt)
ResourceTag(resourceId, tagId)
Tool(id, slug, name, description, status, sortOrder)
ResourceTool(resourceId, toolId, relationType)
Admin(id, authId, role)
DailyMetric(date, eventType, resourceId?, toolId?, count)
```

具体索引和权限设计由技术方案确定，资源搜索的索引至少覆盖名称、简介和标签关联。

## 7. 推荐开发顺序

1. **工程骨架**：路由、主题 token、共用卡片/表单、数据库与管理端认证。
2. **内容闭环**：分类标签 → 后台资源 CRUD → 前台资源列表/详情 → 首页精选。
3. **工具闭环**：先格式转换器验证工具页面范式，再 MCP 生成器、Token 估算器。
4. **资源与工具关联**：从详情页直达工具；必要时预填非敏感公开参数。
5. **上线质量**：SEO、响应式、匿名聚合埋点、错误处理、安全复核、测试与部署。

每阶段完成后检查关联模块；中型功能完成后运行项目约定的代码审查与质量流程。代码提交前需用户确认，提交信息采用类型前缀 + 中文描述。

## 8. MVP 发布门槛（Go / No-Go）

满足以下条件才发布：

- [ ] 首页与资源检索、详情访问畅通，且不存在公开草稿泄漏。
- [ ] 至少 30 条经核实的资源可正常访问。
- [ ] 三个工具的核心路径和主要错误路径通过人工测试。
- [ ] MCP 生成结果经对应客户端的当前官方配置格式复核。
- [ ] 管理后台权限控制和服务端校验生效。
- [ ] 移动端常见视口无核心功能阻断。
- [ ] 页面元数据、站点地图、基础日志和统计可用。
- [ ] 无明文存储/采集用户 API Key 行为。

## 9. 上线后两周的验证方式

不预设虚假的业务表现，以观察数据为主：

| 观察对象 | 数据口径 | 用于回答的问题 |
|---|---|---|
| 搜索 | 搜索次数、无结果率 | 用户是否能找到想要的资源？ |
| 资源详情 | 页面访问量、外链点击 | 内容是否真正有价值？ |
| 工具使用 | 打开次数、执行次数、完成率 | 哪类工具有真实需求？ |
| 导航到工具 | `resource_to_tool_click / resource_view` | “导航 + 工具”的组合是否成立？ |
| 反馈与质量 | 错误报告、无效资源 | 哪些部分优先修复？ |

决策规则：如果某工具打开多但执行少，优先排查入口与交互；如果资源有流量但关联工具使用少，优先改进资源与工具的匹配，而不是盲目扩充功能。
